# LingoMatch 1.1 上线前产品审计

> 审计视角：语言学习×休闲消除产品经理；难以长期坚持、希望“玩着学”的普通用户。

## P0：上线前必须闭环

- [ ] 用 TestFlight 真机跑完新用户、老用户、断网、拒绝权限四条主路径。
- [ ] 买断：购买、取消、失败、恢复购买、退款/撤销后权益回收全部真机验证。
- [ ] 激励广告：正式 Ad Unit、测试设备、UMP/隐私同意、无填充、加载失败、看完发奖、中途关闭不发奖、每日 2 次上限。
- [ ] 体力：免费用户基础 3 点；Say & Blast 完整坚持 60 秒且正确率 ≥70% 获得三星时恢复 1 点，不要求最低目标数；广告把体力 reset 到 3，不是额外叠加。
- [ ] 广告不可用或语音权限被拒绝时，用户仍有明确退路，不出现“必须看广告但广告加载不出”的死锁。
- [ ] 通知：默认关闭、由用户主动开启；拒绝权限后有可理解的设置引导；真机验证次日触发、改时区、重装、关闭、当日完成后取消。
- [ ] 上架前完成 App Store Connect 隐私标签，并与 Firebase、AdMob、账号、分析和语音的真实数据行为逐项对齐。
- [ ] 检查主 App 和 Apple 指定的第三方 SDK 都有有效的 Privacy Manifest，并确认必需原因 API 声明完整。
- [ ] 准备 App Review 测试账号，替换 `docs/app-review-notes.md` 中的账号占位符；写清买断、广告、麦克风和通知的审核路径。
- [ ] 确认 Support URL、Marketing URL、Privacy Policy、Terms 都能在未登录环境打开，且无 404。
- [ ] 接入崩溃监控和版本标记；至少能回答“1.1 发生了多少崩溃、哪个界面最多”。
- [ ] 确认 iPhone/iPad 支持范围；如果声明支持 iPad，必须补齐 iPad 布局真机验收和对应商店截图。
- [ ] 用实际发行包检查 App Icon、启动图、版本号、Build Number、显示名和产品 ID。

## P1：建议首发版完善

- [ ] 通知点击后直接进入“继续学习/上次关卡”，并记录发送、打开、完成三段数据；不只是把 App 打开到默认页。
- [ ] 完整漏斗：`app_open → course_selected → first_valid_match → set_completed → quiz_completed → day_2_return`，并拆分广告请求/展示/完成/失败与买断页展示/点击/购买。
- [ ] 给新用户一次完整的“先爽后限”体验：在他理解消除、听音和复习价值前，不要过早用体力或付费墙打断。
- [ ] 主页提供单一明确的“继续”入口，用户无需再选模式、词组或课程。
- [ ] 一局结束明确告诉用户“刚才学会/复习了哪些词”，让娱乐感与学习成就同时成立。
- [ ] Say & Blast 把通过率、识别失败率、不同母语/机型的差异记录出来；当前三星门槛为 70%，后续用数据验证。
- [ ] 为 Emoji 多义词、地区用法、词性、性别/数变化和语音停顿建立内容 QA 流程；每个新语言都要通过母语者抽检和音频异常扫描。
- [ ] 在用户完成一次可感知的成就后，再适时请求 App Store 评分；不在首次打开或刚遭遇失败时弹出。
- [ ] 对广告、买断、通知和语音模式准备远程开关/降级策略，避免第三方服务异常时必须发版才能解困。

## 产品经理视角：目前最需要优化的五件事

1. **一句话说清产品**：“玩 Emoji 消除，顺便记住外语单词”应成为首页、商店截图和买断页的共同主线。
2. **证明它真的在教**：建立识别→回忆→发音→间隔复习闭环，而不是只让用户重复看 Emoji。
3. **让限制为节奏服务**：体力要促使用户转去 Say & Blast 或第二天回来，不是让刚入门的人感觉被惩罚。
4. **买断价值必须具体**：永久解锁的内容、仍有的使用限制、未来词汇包是否包含，都要用不会过期的文案说清。
5. **发布后要能迅速判断对错**：没有崩溃、漏斗、广告和购买数据，产品就无法迭代。

## 难坚持的学习者视角：会让我离开的时刻

- 打开后要做太多选择，没有一个直接继续的按钮。
- 刚觉得好玩就没体力，但还不知道买断值不值。
- 语音识别把口音或设备问题当成“我学得差”。
- 消除完只得到分数，不知道自己到底记住了什么。
- 通知只会叫我回来，点开后却没有立刻可玩的小任务。
- 界面看起来很热闹，但不清楚今天完成多少就够了。

## 需要产品决策的问题

1. 首发最重要的地区与“母语 → 目标语”组合是什么？不能把所有课程当成同等成熟。
2. iPad 是真正支持的设备，还是只是 Xcode 默认勾选？
3. Say & Blast 对每种目标语都有匹配的识别 locale 吗？还是目前只能稳定支持英语？
4. “早期支持价 US$9.99，之后 US$19.99”的真实截止日期或触发条件是什么？没有真实计划时不应制造虚假紧迫。
5. 未来新词汇包不自动包含在当前买断中，那么现在的“永久解锁”精确解锁边界是什么？
6. 每日体力按本地日历还是服务端时区重置？用户改时区时怎么处理？
7. 首发的成功标准是 D1/D7 留存、完成词数、广告完成率还是买断转化？必须有一个主指标。

## 2026-10-13 已确认的首发决策

- 首发核心市场：日本、美国；香港作为测试市场。
- 不制作繁体中文本地化；香港 App Store 元数据使用英文，App 内对中文用户统一显示现有简体中文。
- iPad 属于正式支持设备，必须纳入布局、旋转、弹窗、广告、购买和商店截图 QA。
- 当前买断永久包含：现有官方 Unicode Emoji 内容在 App 内的游戏使用权。
- 未来可能上线的非官方 Emoji/授权或主题内容不在当前买断中，可以独立 package 收费。
- 早期支持价暂无真实截止日期或涨价触发条件；上线文案不应使用“马上涨价”等虚假紧迫表述。
- 建议首发主指标：**次日有效学习留存率**，即首日完成至少一次有效学习的新用户中，次日回来并再完成至少一次有效学习的比例。

## P2：可在发布后用数据决定

- 新手首日体力宽限、首局不扣体力或首日六点体力的 A/B 测试。
- 70% 三星正确率门槛是否应根据难度、课程和新老用户调整。
- 个性化通知时间、文案风格与频率，而不是默认追求每日推送。
- 根据忘记曲线生成“今天只复习 3 个词”的超短任务。
- 新词汇包、主题活动和轻量连续学习系统，但不在核心玩法未证明前过度堆功能。
